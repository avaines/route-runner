# Project Specification

## Goals

- Describe the outcomes this project must provide.

## Non-Goals

- Describe explicitly excluded behavior and responsibilities.

## Users and Workflows

Describe the intended users and their primary end-to-end workflows.

## Functional Requirements

Use numbered, testable requirements. Include expected behavior for invalid
input, authorization failures, retries, and partial failures where relevant.

## Interfaces and Data

Document APIs, events, storage models, data ownership, and compatibility
expectations.

## Environments and Deployment

Document environment differences, configuration, deployment triggers, approval
requirements, rollback, and verification steps. Never put secret values here.

## Acceptance Criteria

List observable checks that demonstrate the requirements are met.
